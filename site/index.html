Nerf Watch

Is the coding model you pay for getting worse? Every day each product gets real coding tasks, graded by hidden tests and a reviewer, and is compared with its own first week.

      Every day the same coding tasks run through each product as a paying user runs it: Opus 5.5 in Claude Code on a Claude subscription, Grok 4.7 in the Cursor CLI on a Cursor plan, both at high effort. A task passes only if the change passes hidden tests the agent never sees.

      Baseline is each product's first 7 days. Now is the last 7 days after it. Each day runs a different quarter of the tasks and the hardest run once a week, so every recent attempt is compared with how that same task did in the baseline. A week that draws harder tasks is not read as a drop.

      Worse means the change is too large to be chance (under a 1 in 500 chance with no real change). Watch means it moved the wrong way but could still be noise (under 1 in 50). The bar is high because the page makes about forty checks a day. Too few means fewer than 3 attempts in a window. Sustained drop is a separate drift monitor that watches the whole series and only alarms on a drop that holds.

      Attempts are left out of the pass rate, not counted as failures, when the product was down, hit a usage limit, served a different model than requested, or reached the web. Neither agent has web access. Those show under Service as attempts lost.

      Quality scores come from a reviewer model that does not know which product wrote the change. It is a Claude model, so read small quality gaps between the two products with care; each product is only ever compared with itself.
