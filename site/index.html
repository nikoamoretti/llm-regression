How this worksWhere the numbers come from
  • Every day each model gets a few real coding tasks, run the way you would run it: Opus 5.5 in Claude Code on a Claude plan, Grok 4.7 in Cursor on a Cursor plan.
  • A task counts as solved only if the change passes tests the model never sees.
  • A model's first week shows what normal looks like for it. After that, its last 7 days are compared with its own first week. The two models are never ranked against each other.
  • A clear drop is a change too big to be chance (under a 1 in 500 chance). A possible drop is smaller and may still be noise. Each recent task is compared with how the same task went in the first week, so a week of harder tasks is not mistaken for a drop.
  • Runs that fail because the service was down or a usage limit was hit are lost, not counted as failures.
  • Code quality is scored from 1 to 5 by a separate reviewer model that does not know which product wrote the change.
