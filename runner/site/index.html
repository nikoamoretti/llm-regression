How this works

Every day the same coding tasks run through each product as a paying user would run it: Opus 5.5 in Claude Code on a Claude subscription, and Grok 4.7 in the Cursor CLI on a Cursor plan, both at high effort. A task counts as passed only when the change passes hidden tests the agent never sees. Tasks are frozen benchmark tasks plus real bug fixes mined from a project's history; the multi-commit hard tasks run once a week each.

Each day runs a different quarter of the tasks, so daily rates move with the mix. The verdict comes from a drift monitor that compares each product with its own first week, adjusted for which tasks ran, and only reports a decline after a sustained drop.

Attempts are excluded, not failed, when the product was unavailable, hit a usage limit, served a different model or reasoning level than requested, or reached the web. Neither agent has web access, so neither can look up a task's upstream fix.

The quality reviewer is a Claude model. It may favour Claude's style, so compare each product with its own history before reading small gaps between them.
