      Every day a rotating set of real coding tasks runs through each product the way a paying user runs it: Opus 5.5 in Claude Code on a Claude subscription, Grok 4.7 in the Cursor CLI on a Cursor plan, both at high effort. A task passes only if the change passes hidden tests the agent never sees.

      Each model is measured against itself. Baseline is its first 7 days; last 7 days is the most recent week after that. Each day runs a different quarter of the tasks and the hardest run once a week, so single days move with the mix: the bold line is a 7-day rolling rate, and every check below compares each recent attempt with how the same task did in the baseline.

      Worse means a change too large to be chance (under 1 in 500 with no real change). Watch means it moved the wrong way but could still be noise (under 1 in 50). The bar is high because the page makes many checks a day. Too few means fewer than 3 attempts in a window. Sustained drop is a separate drift monitor that only alarms on a drop that holds.

      Attempts are left out of the pass rate, not counted as failures, when the product was down, hit a usage limit, served a different model than requested, or reached the web. Neither agent has web access. Those count as attempts lost.

      Quality scores come from a reviewer model that does not know which product wrote the change.
